ISO/IEC 25010:2023 SQuaRE

Instrumento de autoevaluación interactivo basado en el estándar internacional de calidad de software. Evalúa tu proyecto contra 9 características de calidad en 27 preguntas.

Cómo usar esta evaluación

Para cada pregunta, selecciona la opción que mejor describe el estado actual de tu proyecto. Las opciones van de "Cumple completamente" (4 puntos) a "No cumple" (1 punto). Al finalizar, obtendrás un diagnóstico de cumplimiento por característica.

1. Adecuación Funcional
Grado en que el software provee funciones que satisfacen necesidades declaradas
—
Completitud Funcional: El código generado implementa todas las funcionalidades definidas en los requisitos sin omitir ninguna.
Corrección Funcional: Los resultados del código son exactos y precisos para todos los casos de uso definidos.
Pertinencia Funcional: Las funcionalidades son relevantes para el problema; no incluye funciones innecesarias que aumenten complejidad.
⚡
2. Eficiencia de Desempeño
Desempeño relativo a la cantidad de recursos usados
—
Comportamiento Temporal: El código responde dentro de tiempos aceptables para el contexto de uso.
Utilización de Recursos: El código hace uso eficiente de memoria, CPU, y almacenamiento sin consumo innecesario.
Capacidad: El sistema maneja el volumen máximo esperado de datos sin degradación del desempeño.
🔗
3. Compatibilidad
Grado en que comparte entorno e intercambia información con otros sistemas
—
Coexistencia: El código coexiste correctamente con otros componentes sin generar conflictos o interferencias.
Interoperabilidad: Los módulos son interoperables con APIs externas, servicios de terceros y protocolos requeridos.
Compatibilidad de dependencias: No introduce conflictos con librerías, frameworks o herramientas existentes.
🖥️
4. Capacidad de Interacción
Grado en que puede ser usado con efectividad, eficiencia y satisfacción
—
Usabilidad: El sistema es intuitivo; los usuarios pueden aprender a usarlo sin capacitación extensa.
Protección ante errores: Valida entradas, solicita confirmación antes de operaciones irreversibles, presenta mensajes claros.
Accesibilidad: Es accesible para diferentes perfiles de usuario; se describe a sí mismo claramente.
🛡️
5. Fiabilidad
Grado en que realiza funciones especificadas sin fallos por un periodo determinado
—
Ausencia de fallos: El código opera sin crashes, comportamientos inesperados ni errores silenciosos.
Disponibilidad y tolerancia a fallos: El sistema está disponible cuando se necesita; los errores se manejan controladamente.
Recuperabilidad: Se recupera correctamente después de fallos; restaura el estado previo y protege la integridad de datos.
🔐
6. Seguridad
Grado en que protege información, datos y acceso no autorizado
—
Confidencialidad e integridad: Los datos son accesibles solo para usuarios autorizados; no expone información sensible.
No-repudio y responsabilidad: Las operaciones críticas quedan registradas de forma trazable y auditable.
Autenticidad y resistencia: Verifica identidad de acceso; resiste ataques comunes (SQL injection, XSS, fuerza bruta).
🔧
7. Mantenibilidad
Grado de efectividad para ser modificado por mantenedores previstos
—
Modularidad y reusabilidad: Los módulos son independientes con bajo acoplamiento; pueden modificarse sin afectar otros componentes.
Analizabilidad: El código es legible, está comentado, y el flujo lógico es comprensible sin necesidad de la IA que lo generó.
Capacidad de ser modificado y probado: Puede extenderse con nuevos requisitos; puede probarse unitaria e integradamente.
🌿
8. Flexibilidad
Grado en que puede adaptarse a cambios de requisitos o entornos
—
Adaptabilidad: Puede adaptarse a nuevos requisitos sin refactorizaciones mayores ni reescrituras completas.
Escalabilidad: Puede escalar para mayor carga de usuarios, datos o transacciones sin cambios arquitecturales profundos.
Instalabilidad y reemplazabilidad: Puede instalarse/desinstalarse correctamente; los componentes pueden reemplazarse por versiones mejores.
⚠️
9. Protección (Safety)
Grado en que mitiga el riesgo de daño a personas, datos o sistemas
—
Restricción operativa: Implementa controles que evitan operar en condiciones no autorizadas o peligrosas.
Protección ante fallos: Ante un fallo, el sistema pasa a un estado seguro conocido; advierte a usuarios antes de acciones peligrosas.
Integración segura: Las integraciones con sistemas externos usan interfaces seguras validadas; un fallo externo no compromete el sistema.
