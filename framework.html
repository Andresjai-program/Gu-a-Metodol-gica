Arquitectura metodológica integrada

Este documento define cómo se conectan los seis módulos operativos, la evaluación ISO/IEC 25010, la auditoría OWASP y los prompts de ingeniería avanzada. No es una colección de plantillas: es un sistema de gobernanza técnica para software asistido por IA.

Gobernanza Human-in-the-Loop

Modelo operativo obligatorio: ningún output de IA se integra sin validación y aprobación humana documentada.

Anatomía de un módulo (P01–P06)

Cada módulo en el handbook sigue esta estructura de diez bloques. Garantiza profundidad técnica y evidencia para auditoría académica o profesional.

  1. Objetivo metodológico — Qué capacidad de ingeniería se desarrolla o protege.
  2. Riesgo mitigado — Riesgo técnico, cognitivo, ético o normativo con referencia empírica cuando aplique.
  3. Estándares — ISO 25010, OWASP, SOLID, Clean Code, NIST, normativa aplicable.
  4. Técnica de prompt engineering — CoT, few-shot, reflexión, self-consistency, adversarial o tree-of-thoughts.
  5. Prompt avanzado — Plantilla profesional con fases, restricciones y formato de salida estructurado.
  6. Resultado esperado — Artefacto concreto (spec, informe, matriz, tests).
  7. Validación técnica — Criterios verificables antes de continuar.
  8. Métricas — Indicadores cuantificables o umbrales.
  9. Auditoría — Preguntas de control y cruce con ISO/OWASP.
  10. Evidencia — Qué documentar para trazabilidad (commit, ADR, checklist firmado).
